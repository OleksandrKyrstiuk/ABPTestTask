# Conference Hall Booking API

## Description

REST API for managing conference halls, bookings, and rental price calculation.

The API allows users to create, update, and delete halls, search for available halls, create bookings with time-based pricing, and retrieve business reports and statistics.

## Technologies

* .NET 9
* ASP.NET Core Web API
* C#
* Swagger / OpenAPI
* System.Text.Json
* DataAnnotations

## Architecture

The project separates responsibilities between controllers, services, DTOs, and models.

* **Controllers** — handle HTTP requests and return HTTP responses.
* **Services** — contain the application's business logic.
* **DTOs** — define data transfer and validation models for API requests.
* **Models** — represent the application's data entities.
* **GlobalExceptionHandler** — provides centralized exception handling and consistent HTTP error responses.

### Services

* **HallService** — manages hall creation, updating, deletion, validation, and search.
* **BookingService** — handles booking creation, availability checks, and booking conflict detection.
* **PricingService** — calculates rental prices and additional service costs.
* **ReportService** — generates business reports and booking statistics.

## Pricing Rules

Rental prices are calculated hourly depending on the booking time.

| Time        |    Pricing |
| ----------- | ---------: |
| 06:00–09:00 |       -10% |
| 09:00–12:00 | Base price |
| 12:00–14:00 |       +15% |
| 14:00–18:00 | Base price |
| 18:00–23:00 |       -20% |

Bookings are available from **06:00 to 23:00**.

The price of selected additional services is added to the rental price.

## API Endpoints

### Hall Management

| Method | Endpoint           | Description                |
| ------ | ------------------ | -------------------------- |
| POST   | `/api/Hall`        | Create a new hall          |
| PUT    | `/api/Hall/{id}`   | Update an existing hall    |
| DELETE | `/api/Hall/{id}`   | Delete a hall              |
| POST   | `/api/Hall/search` | Search for available halls |

### Booking

| Method | Endpoint       | Description          |
| ------ | -------------- | -------------------- |
| POST   | `/api/Booking` | Create a new booking |

### Reports

| Method | Endpoint                  | Description                            |
| ------ | ------------------------- | -------------------------------------- |
| GET    | `/api/reports/overview`   | General booking and revenue statistics |
| GET    | `/api/reports/halls`      | Statistics for each hall               |
| GET    | `/api/reports/services`   | Statistics for additional services     |
| GET    | `/api/reports/peak-hours` | Booking statistics grouped by hour     |

Report endpoints support optional `from` and `to` query parameters for filtering data by date range.

## Storage

The project uses a JSON file for data storage:

```text
Data/data.json
```

The file contains collections of:

* halls
* additional services
* bookings

JSON storage is used to keep the solution simple and self-contained without requiring an external database.

## Business Reports

The API provides several reports that can be used for business analysis:

* **Overview** — total bookings, total revenue, average booking price, and average booking duration.
* **Halls** — booking count, revenue, and total booked hours for each hall.
* **Services** — usage frequency and revenue generated by additional services.
* **Peak Hours** — booking frequency grouped by starting hour.

These reports can help analyze demand, hall utilization, peak booking periods, and the performance of additional services.

## Error Handling

The API uses standard HTTP status codes:

* `200 OK` — request completed successfully.
* `201 Created` — resource was successfully created.
* `400 Bad Request` — invalid request data.
* `404 Not Found` — requested resource was not found.
* `409 Conflict` — request conflicts with existing data.
* `500 Internal Server Error` — unexpected server error.

Exceptions are handled centrally by `GlobalExceptionHandler`, which converts application exceptions into appropriate HTTP responses.

## API Documentation

The API is documented using **Swagger / OpenAPI**.

Swagger provides information about available endpoints, request parameters, request models, response codes, and allows API endpoints to be tested directly from the browser.
